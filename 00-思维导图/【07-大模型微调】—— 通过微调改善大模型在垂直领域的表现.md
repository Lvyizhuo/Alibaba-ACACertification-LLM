# 大模型微调
## **课程前言**
- 微调类比考生闭卷考试备考，需反复打磨、成本高
- 微调易引发大模型"灾难性"遗忘，高效微调也会让模型专事专用
## **学习目标**
- 了解大模型微调适用场景及流程
- 了解常见微调方法的原理
- 掌握利用阿里云服务做大模型微调的方法
## **1 关于微调的核心认知**
- 1.1 定义：对预训练大模型做针对性补习，用领域数据二次训练适配特定需求
- 1.2 可实现效果
  - 风格化：如训练为医疗专家，精准解答专业问题
  - 格式化：如对接业务系统，端到端自动化调用接口
- 1.3 微调的意义：平衡模型效果与成本，低参模型微调后逼近高参模型表现
- 1.4 微调的关键
  - 需特定领域高质量数据，获取难度高、成本大
  - 需适配参数，易出现过拟合/欠拟合，需反复迭代
- 1.5 微调的实施
  - 效果示例：为大模型注入学校专属知识，实现精准问答
  - 1.5.1 业务决策：评估需求匹配度、数据质量、合规隐私、资源技术可行性，做ROI分析
  - 1.5.2 微调流程：数据准备→模型选择→模型微调→模型评测→模型集成→测试与优化→模型部署→监控与维护→持续迭代
- 1.6 微调的方式
  - 微调的"微"：数据规模小、训练时间短
  - 分类：全参微调（调整所有参数，成本高）、高效微调PEFT（仅调部分参数，降本提效）
  - 主流PEFT方法
    - LoRA：低秩适应，新增低秩矩阵旁路，仅训旁路参数，效果接近全参、通用性强
    - Adapter Tuning：插入Adapter层，仅训该层参数，新增参数量少，推理有额外消耗
    - Prefix Tuning：构造任务相关虚拟token前缀，仅训前缀参数，避免灾难性遗忘，长序列生成表现好，占用上下文窗口
    - Prompt Tuning：仅在输入层加可训练prompt tokens，训参极少、灵活适配多任务，复杂生成任务效果一般
  - PEFT方法共性问题：推理延迟、优化难度、占用tokens等，LoRA相对更高效
## **2 阿里云大模型微调服务**
- 有算法背景：选PAI（DSW在线开发、DLC分布式训练、EAS模型部署）
- 有虚拟机/容器经验：选GPU云服务器、ACK云原生AI套件
- 无算法背景：选百炼，开箱即用的界面化调优、评测管理能力
- 百炼相关：含推理/训练/部署三类计费，样本量小也可能耗时久、成本高
